# Orphaned and stale files — review record (V17.6.9)

**Source:** the GitHub Actions log `logs_104051351287` (test stage) — *54 orphaned legacy TypeScript files* reported under `src/`, plus the failing historical test files. **Finding:** none of the 59 files is part of the V17.6.8 package, none is imported from `src/main.ts` (checked with the production source-set walker), and none is imported by any remaining test. The V17.6.8 package passes 266/266 tests without them. They exist only in the target repository (a package copied over a repository never deletes files).

**Review of the hosted vault names in the log.** `looksLikeVaultFile`, `hostedVaultUrl`, `tokenSource` and the "Hosted Secret Vault" message belong to `src/v17/services/hostedVault.ts` (V17.5.8) and the V17.5.8 / V17.6.0 tests. V17.6.3 replaced that route by the published copy (`publishedData.ts` + `vaultRetrieval.ts`, `via: 'repository-published'`), and the vault-retrieval messages were rewritten (no "Hosted Secret Vault"). Restoring the old module would re-introduce superseded behaviour and a second implementation, so it was **not** restored and **no stub** was created. The behaviour those tests protected (same-origin hosted copy, no GitHub request, fallback page not taken for a vault, nothing shown) is covered against the production modules in `test/v1769.test.mjs`.

**Removal.** Not automatic. After reviewing this list: `node scripts/prune-orphans.mjs --delete` and `node scripts/prune-stale.mjs --delete` (each re-verifies at deletion time that `src/main.ts` still does not reach the file / `package.json` does not run the test, and only touches paths in `scripts/stale-files.json`). CI runs `npm run check:stale` and fails until the checkout is clean.
