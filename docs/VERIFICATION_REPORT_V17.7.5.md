## Plain answers
**Does the automatic delivery of the central PAT to an Azure-hosted broker still exist?** **No.** The former `deploy-broker.yml` copied `SQLA_GITHUB_PAT` and `SQLA_SESSION_SECRET` (plus the client id, origins and allowed repositories) to an Azure App Service as application settings. It needed Azure credentials, so it is gone. `package-repo-broker.yml` only builds, tests and packages the broker and uploads an artifact; **no workflow reads or delivers the PAT any more**. The operator sets `SQLA_GITHUB_PAT` etc. as environment variables on their own host (`docs/CENTRAL_PAT.md`). This is the **only token-delivery behaviour that changed.** Everything else of the token synchronization — the in-app logic, the broker service and its environment-variable contract, `publish-data.yml`, `verify-repo-pat.yml` — is unchanged, so an existing broker deployment keeps working. If automatic delivery must stay, say so: `deploy-broker.yml` would then be restored as an optional, Azure-credentialed workflow and explicitly exempted from the "no Azure" rule.

**Which workflows still need an operator-provided secret, and why?** Only the two token-synchronization workflows, both optional and not required for building or deploying: `publish-data.yml` reads `SQLA_DEVICE_TOKEN` and `SQLA_VAULT_PASSPHRASE` (only when the **central token vault** is rebuilt on request), `verify-repo-pat.yml` reads `SQLA_GITHUB_PAT` (the weekly PAT check). They are frozen because changing the secrets they read would change token synchronization. `deploy-pages.yml` and the two packaging workflows read no secret.

## Caveats you should know
* **The V17.7.4 reference is a rebuild, not the original zip.** The original was not available. From your 359-file text bundles I restored the favicon (from `dev-dist`), three compiler files (`bin/tsc`, `LICENSE.txt`, `ThirdPartyNoticeText.txt` — each only because its SHA-256 equals the value in `CHECKSUMS.json`) and re-created the two Python browser suites (from the earlier development turns). Byte identity with the original zip cannot be claimed. Use the original V17.7.4 zip for rollback if you still hold it.
* **V17.7.4 had a defect** that its own report hid: one test failed outside an environment with a global `NODE_PATH`. Fixed in V17.7.5.
* **Earlier test files were edited.** The instructions said the token / vault / central / sync tests run unchanged; five of the listed files (`v1762`, `v1763`, `v1764`, `v1768`, `v1769`) had to be edited because they pinned things this release is required to remove (the `npm ci` fallback, the Azure broker workflow and its preflight) or the V17.7.4 `node_modules` defect. Each edit is an exact recorded replacement with a reason and is provably reversible to the V17.7.4 hash (`test/fixtures/test-adaptations-v1775.json`, section 5 of the inventory). Six of the listed files were not touched.
* **`server/analytics-service.mjs` changed in two comments only** (it named a cloud product), so that the packaged artifact holds no Azure reference; every code line is identical.
* **Remaining words, documented not removed:** the `release/staticwebapp.config.json` static hosting file, the `.openai.azure.com` host allowance of the optional AI feature, a historical comment in the frozen broker and relay scripts, and the `npm run` hints in a few script messages (one is pinned by a V17.6.4 test).
