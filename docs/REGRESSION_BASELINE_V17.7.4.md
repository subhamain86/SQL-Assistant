# Regression baseline — V17.7.4

* **Reference:** the V17.7.3 package. The original V17.7.3 zip was **no longer available** when V17.7.4 was started (the working files of the previous session were gone); V17.7.3 was therefore **rebuilt** from the supplied V17.7.2 sources plus the recorded V17.7.3 change set, and verified before anything was changed: the V17.7.3 Node tests (`v1773` — 41 tests — with `v1772`, `v1771`, `v1769`) passed as on the original delivery (only the two hygiene tests that need the historical browser suites failed, exactly as on the untouched V17.7.2), and the V17.7.3 browser suite passed **84/84**. That rebuilt tree is the rollback package `SQL-Assistant-V17.7.3.zip`.
* **UI pin:** `test/fixtures/ui-baseline-v1773.json` — SHA-256 of every `src/ui` module, the style sheet and the favicon of the rebuilt V17.7.3. `test/v1774.test.mjs` requires every module not listed in `changedIn1774` to be byte-identical, the V17.7.3 bytes of the style sheet to be an exact prefix (append-only) and the favicon to be unchanged. The V17.7.2 pins of V17.7.3 (`ui-baseline-v1772.json`) still hold.
* **Historical tests changed (intent kept, nothing weakened):** the V17.7.3 version test became a documented historical test (current-version assertions moved to `v1774`, as in each release before); `v1769` no longer requires the historical suite name `browser_test_v1769.py` in `test:browser` (it requires a 17.7.x suite and `test:browser:all`); `v1763` accepts the path filter that keeps analytics commits from starting the publication workflow.
* **V17.7.3 service provider:** `server/analytics-service.mjs` is byte-identical; all 41 V17.7.3 tests and the 84 V17.7.3 browser checks pass against V17.7.4.
