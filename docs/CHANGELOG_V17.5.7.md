### SQL Assistant 17.5.7 — what changed

**Baseline.** The package named by your links, `SQL-Assistant-V17.5.5.zip`, is the only project source that could be opened (see SOURCE_PROVENANCE.md: a V17.5.6 package exists in your OneDrive as an extracted folder, but its source could not be read from here). V17.5.5 was built and tested unchanged first (102/102 Node tests, 75/75 browser checks). V17.5.7 therefore contains **everything requested for V17.5.6 and V17.5.7**, re-implemented on top of V17.5.5 — if you hold a V17.5.6 build, compare it with this one (`docs/` lists every file touched). UI design, the style sheet (byte-identical), file formats, encryption, existing storage keys, repository paths and all SQL / schema functionality are unchanged — no migration. V17.5.5 is not modified and is the rollback (DEPLOYMENT.md).

#### Already true in V17.5.5 (traced first, kept, re-tested)
The three Schema cards, no *Schema passphrase — encrypted synchronization* card in Settings → Schema Management, *Push Secret Vault to Repository* as the only push and no repository card in Settings → Secret Vault, the default Vault Sync Passphrase pre-filled (masked), a validated transactional schema pull that never overwrites valid local schemas.

#### Cross-device recovery — what is supported and what is not
* **Supported and tested on two separate browser profiles:** Device A validates and stores the token, pushes the encrypted vault (Settings → Secret Vault). Device B (no token) opens Schema → Pull Schema, imports the vault file with the Vault Sync Passphrase, the token is decrypted and validated locally, stored only as ciphertext, never displayed, and is then used internally for Pull Schema and Push.
* **A private repository cannot be read without a credential**, so a brand-new device cannot fetch the vault from it by itself. It needs the vault file (`sql-assistant-data/vault/secret-vault.v17.enc.json`, downloadable from GitHub by anyone with access) **or** a token already on the device. This is the architectural constraint named in the request; zero-interaction recovery would need a backend or key-management service and was **not** built. Retrieve works directly for a public repository and for a device that already has a token.
* The passphrase must be supplied on Device B (pre-filled with the default; replace it when the vault was pushed with another one). See SECURITY.md for why an administrator-chosen passphrase is strongly recommended.
